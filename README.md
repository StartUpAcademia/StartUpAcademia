# StartUpAcademia — 介護記録アシスタント

スタートアップアカデミア開発用。ワイヤレスイヤホン等での発話だけで，施設ごとに異なる
フォーマットに沿った介護記録をリアルタイムに作成できるWebアプリのプロトタイプです。

## 実装範囲

- **P-1** 記録フォーマットの初期設定（記録用紙の撮影 → AIによる項目抽出 → 確認・編集）
- **P-2** 音声入力による記録作成（「記録開始」「送信」という発話ワードで開始・送信、Web Speech API）
- **P-3** 個人ページでの記録確認（入居者ごとのタイムライン表示、未入力項目のハイライト）

## セットアップ

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000) をGoogle Chromeで開いてください（音声認識はChromeの機能に依存します）。

写真からの項目抽出・発話内容の構造化にはAnthropic Claude APIを使用します。`ANTHROPIC_API_KEY`
環境変数が未設定の場合は，開発用のモック応答にフォールバックします。

```bash
# .env.local
ANTHROPIC_API_KEY=sk-ant-...
```

## デプロイ

GitHubリポジトリをVercelにインポートすることで，push時の自動デプロイが有効になります。
APIキーはVercel側の環境変数に設定し，ブラウザには公開しません。

## ホームでのハンズフリー音声記録（MVP）

1. `npm run dev` を実行し、`http://localhost:3000` を開きます。
2. 初回はホームの「マイクを許可して開始」を押して許可します。許可済みならホーム表示時に自動で待機を開始します（許可状態を取得できないブラウザではボタン操作が必要です）。
3. 案内が終わってから、発話ごとに短く区切って話します。
   - 「Hey Care」または「ヘイケア」
   - 「田中さん」（同姓の候補がある場合はフルネームで聞き返します）
   - 「水分150ミリリットル」
   - 読み上げと確認カードを確認して「はい」「登録」「記録」
   - 「排便あり」→ 確認後「はい」（同じ利用者へ続けて登録）
   - 「END」または「エンド」
4. 誤りがある場合は確認中に「訂正」「違います」と話し、内容を話し直してください。
5. 「入居者ごとの記録を見る」で日時・記録者・音声入力・内容を確認できます。

保存がゼロ件のまま END で終了すると「音声記録未完了・要確認」を保存します。
利用者確定前の場合は「利用者未指定（要確認）」に表示します。事故や異常があったと断定する記録ではありません。
保存に失敗した場合は終了を確定せず、再試行を案内します。

### 制約と構成

- マイクの初回許可操作が必要です。許可済みなら自動起動します。実際の音声認識開始通知を受けるまで有効表示にはせず、接続タイムアウトや権限拒否を案内します。ページが前面にある状態で使用してください。画面ロック中・バックグラウンドの常時ウェイクワード検出は保証しません。
- Web Speech API の対応状況はブラウザ・端末に依存します。認識にはブラウザ提供の外部サービスへの通信が発生する場合があります。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)
- 読み上げ中はマイク認識を停止します。案内が終わり「マイク：聞き取り中」と表示されてから回答してください。
- 入居者は `lib/constants.ts` の `ALL_RESIDENTS`、記録者は既存の `CURRENT_STAFF`（佐藤）を使用します。本物の認証は未実装です。
- 保存は既存の `localStorage`（`care.records`）を利用します。同じブラウザ内のデモ用で、端末間共有やサーバーへの永続化はありません。
- MVP の項目分類はルールベースです。水分量以外は発話を保持します。設定項目に対応しない場合は特記事項に原文を残し、項目がない場合も記録の原文・カテゴリを保持します。
- コマンドは発話全体との一致で判定し、記録本文と分離します。名前はフルネームまたは姓の一致のみで、推測による別人への割り当ては行いません。
- `lib/voice/session.ts` が状態遷移、`lib/voice/browserSpeech.ts` が交換可能な認識・読み上げサービス、`app/components/VoiceRecordCard.tsx` が表示を担当します。
- 従来の `/main`、`/confirm`、フォーマット設定はそのまま利用できます。新しい確認後保存・END フローはホームの音声カードで利用します。

### 検証

```bash
node --test tests/*.test.mjs
npx tsc --noEmit
```

開発モードのホームには「開発用：発話シミュレーション」があります。1発話ずつ入力して、同じ状態管理・保存処理をマイクなしで確認できます（認識精度の検証とは異なります）。

### マイクに接続できないとき

- 同じPCでは `http://localhost:3000` を利用してください。スマホから `http://192.168...` へアクセスするとマイクを使えないため、HTTPSでの配信が必要です。
- ブラウザのサイト設定のマイク許可と、Macの「システム設定 → プライバシーとセキュリティ → マイク」でブラウザの許可を確認してください。
- マイクの許可と音声認識サービスへの接続は別です。「音声認識に接続しています」から進まない場合は12秒でエラーを表示し、再接続できます。
- 初回の許可画面に応答しない場合は20秒で案内を表示します。遅れて許可されたマイクのストリームも解放し、二重起動を防ぎます。
